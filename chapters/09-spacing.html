Chapter 09

Spacing systems

Spacing is the foundation people notice least and feel most. It's what makes a screen feel calm or cluttered, organised or confusing. And because everyone decides it "by eye", it's usually the first thing to drift.

Read this if

Your screens feel slightly "off" but nobody can say why, design reviews keep turning into debates about padding, or you need both a compact and a roomy layout.

What you'll leave with
  1. A base unit and a short list of spacing values, and why they work.
  2. A simple way to think about space inside and between things.
  3. How to offer compact and comfortable versions of the same screen.

09.1Why spacing matters so much

Space does three jobs on a screen. It groups things: we automatically read items that sit close together as belonging together. It shows importance: things with more room around them feel more important. And it creates rhythm: a repeating beat that makes a page feel calm and intentional.

When spacing is chosen screen by screen, each value can be defended on its own, but together they're noise: 13 pixels here, 14 there, 22 somewhere else. People using the product don't notice the numbers. They notice that it feels a bit untidy, and they trust it a little less. Look at the same form below, spaced two ways.

09.2Picking a base unit

A spacing system starts with one small number, the base unit, and every spacing value is a multiple of it. Think of it like the smallest Lego stud: everything you build is a whole number of studs. The two common choices are 8 pixels and 4 pixels.

8px base

Fewer, clearer choices

Easy to think about, and most screen sizes divide neatly by 8. Atlassian's design system, for example, builds its spacing on an 8px base, with a few smaller steps for tight spots.[[c:atlassian-spacing]] [[doc]]

4px base

Finer control for busy screens

Lets you use 12, 20 and 28, which matter for small components, icons and line spacing. Google's Material uses a 4dp grid for text and icons alongside an 8dp grid for layout.[[c:m3-structure]] [[doc]]

[[prac]] Our recommendation

Use a 4px base with an 8px rhythm. Every value is a multiple of 4, and most of the values people actually reach for are multiples of 8. You get the precision small components need without the endless choice of "any number will do". Set line spacing for text (Chapter 08) to the same 4px grid, so text and boxes share one rhythm.

09.3The spacing scale

The scale is the fixed list of spacing values people can choose from. It should have lots of options at the small end, where 4 pixels is a visible difference, and only a few at the large end, where nobody can tell 64 from 68.

09.4Space inside things, space between things

It helps to think about three kinds of space. Nathan Curtis gave them simple names that have stuck: inset (padding inside a box), stack (space between things stacked vertically) and inline (space between things side by side).[[c:curtis-space]] Naming the kind of space, not just the amount, makes design specs and code reviews much clearer.

A useful rule of thumb is to use smaller values inside things and larger values between bigger groups:

Where the space isTypical valuesExamples
Inside a component4–16pxGap between an icon and its label; padding inside a button or input
Between related items8–16pxA label and its field; one field and the next; list items
Between groups24–32pxSections of a form; gaps between cards
Between page sections40–64pxMajor sections of a page
Page edges16–80pxGrows with screen size (see Chapter 10)

The golden rule: space within a group must always be clearly smaller than space between groups. A handy way to guarantee it is to jump at least two steps on the scale between levels: 8 → 16 → 24 or 32. That keeps relationships obvious, even when different designers make their own sensible choices. [[prac]]

09.5Compact and comfortable

Think about two very different people using the same invoices table. An accountant at month-end wants to see 200 rows without scrolling. A small business owner checking one invoice on a Sunday wants things roomy and easy to tap. Density is how much fits in a given space, and good systems let you offer both, by switching a few spacing values rather than building separate components.

There's a floor to how compact you can go, set by people's fingers and by accessibility rules. WCAG 2.2 requires click and tap targets of at least 24 by 24 pixels, with some exceptions.[[c:wcag-target]] [[std]] For touchscreens, platform guidelines go further: Apple recommends at least 44 by 44 points,[[c:hig-a11y]] and Google's Material recommends 48 by 48.[[c:m3-structure]] [[doc]] So compact modes are for mouse-and-keyboard use on desktop. Don't make them the default on phones.

09.6Spacing on different screens, and common mistakes

Here's a simple principle. Spacing inside components shouldn't change with screen size: a button has the same padding on a phone and a laptop. Spacing in the layout should: the margins around the page and the gaps between sections grow when there's more room. You can build that split into your named values. For engineers, it looks like this:

/* The scale itself never changes */
--space-2: 8px;  --space-4: 16px;  --space-6: 24px;  --space-10: 40px;  --space-16: 64px;

/* Layout spacing grows on bigger screens */
--space-page-margin:  var(--space-4);     /* 16px on phones          */
--space-section-gap:  var(--space-10);
@media (min-width: 840px) {
  --space-page-margin: var(--space-6);   /* 24px on larger screens  */
  --space-section-gap: var(--space-16);
}

/* Component spacing changes with density, not screen size */
--space-control-inset-x: var(--space-3);

Four mistakes we see again and again

Mistake

"Just this once" values

Each one seems harmless. Fifty of them add up to a second, invisible spacing system. Set up an automatic check for spacing values that aren't on the scale.

Mistake

The same spacing everywhere

Using 16px for everything removes the grouping signal, and groups disappear. Vary space on purpose.

Mistake

Components with built-in outside margins

A component that adds its own space around itself collides unpredictably with others. Let the container decide the gaps between its contents.

Mistake

Forgetting about line spacing

A 16px gap between two blocks of loosely spaced text looks bigger than 16px. Keep text on the same 4px rhythm so measured and visible space match.

Spacing checklist

  • A base unit chosen (we recommend 4px with an 8px rhythm)
  • A fixed list of about 12–14 values
  • Names that tell you the size
  • Inset, stack and inline used in specs
  • Space within groups clearly smaller than space between them
  • Compact and comfortable modes; touch targets big enough
  • Component spacing fixed; layout spacing grows with screen size
  • An automatic check for off-scale values

The short version

What to remember from this chapter

  1. Space groups things, shows importance and sets rhythm. It's never just "empty".
  2. Pick a base unit (4px is our recommendation) and a short, fixed list of values.
  3. Keep space inside groups clearly smaller than space between them.
  4. Offer density modes by changing a few values, and respect minimum tap sizes on touchscreens.
