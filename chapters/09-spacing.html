Chapter 09

Spacing systems

Spacing is the foundation people notice least and feel most. It creates grouping, hierarchy and rhythm. Left to individual judgement, it is also the first thing to drift.

Read this if

Your screens feel "slightly off" without anyone being able to say why, reviews keep debating padding, or you need to support compact and comfortable densities.

What you'll leave with
  1. A base unit and a spacing scale, with the reasoning behind both.
  2. A clear model for component spacing versus layout spacing, and for density modes.
  3. Spacing tokens, and the mistakes to avoid when introducing them.

09.1Why spacing systems matter

Space does three jobs in an interface. It groups related things (the Gestalt principle of proximity: elements close together are read as belonging together). It creates hierarchy, because more space around something gives it more importance. And it sets rhythm, a repeated cadence that makes a screen feel calm and intentional.

When spacing is chosen per screen, each value is defensible on its own, but together they are noise: 13px here, 14px there, 22px somewhere else. Users don't consciously notice the numbers. They notice that the interface feels slightly unresolved.

09.2Choosing a base unit

A spacing system starts with a base unit, and every spacing value is a multiple of it. The two common choices are 8px and 4px.

8px base

Fewer, more distinct values

Easy to reason about; most screen sizes divide by 8. Used by many systems as the primary unit: Atlassian's spacing scale is built on an 8px base, with smaller half and quarter steps for tight UI.[[c:atlassian-spacing]] [[doc]]

4px base

Finer control for dense UI

Allows 12px, 20px and 28px, which matter for small components, icon alignment and line-heights. Material uses a 4dp baseline grid for type and icons alongside its 8dp layout grid.[[c:m3-structure]] [[doc]]

[[prac]] Our recommendation

Use a 4px base with an 8px rhythm: every value is a multiple of 4, and most of the values people reach for are multiples of 8. You get the precision dense components need without the indecision of a scale where every value is available. Align line-heights (Chapter 08) to the same 4px grid so text and boxes share one vertical rhythm.

09.3The spacing scale

A scale is the closed list of spacing values the system offers. It should be dense at the small end, where 4px is a visible difference, and sparse at the large end, where 64px versus 68px is not. A roughly geometric progression does this naturally.

09.4Component spacing and layout spacing

It helps to separate spacing inside components from spacing between them. Nathan Curtis describes three kinds: inset (padding inside a container), stack (vertical space between stacked elements) and inline (horizontal space between elements in a row).[[c:curtis-space]]

LevelTypical rangeExamples
Within a componentspace.1–space.4 (4–16px)Icon-to-label gap, button padding, input padding, chip gap
Between related elementsspace.2–space.4 (8–16px)Label to field, field to field, list items
Between groupsspace.6–space.8 (24–32px)Form sections, card grid gaps, toolbar to content
Between sectionsspace.10–space.16 (40–64px)Page sections, settings groups
Page marginsspace.4–space.20 (16–80px)Responsive; see Chapter 10

The proximity rule: space within a group must always be clearly smaller than space between groups. A useful heuristic is to step at least two scale steps between levels (8 → 16 → 24/32). That keeps relationships unambiguous even when designers make reasonable local choices. [[prac]]

09.5Density: compact and comfortable

Density is how much information fits in a given area. Different users and tasks need different density: an analyst scanning 200 rows wants compact; a first-time user filling a form wants comfortable. Systems handle this with density modes that remap component sizes and spacing, not with separate components.

Density has a floor set by accessibility. WCAG 2.2 SC 2.5.8 (Target Size, Minimum, level AA) requires pointer targets of at least 24 × 24 CSS px, with some exceptions such as adequately spaced targets and inline links.[[c:wcag-target]] [[std]] Platform guidelines go further for touch: Apple recommends at least 44 × 44pt for controls,[[c:hig-a11y]] and Material recommends 48 × 48dp touch targets.[[c:m3-structure]] [[doc]] Compact modes are for pointer-driven desktop use; never ship them as the default on touch devices.

09.6Responsive spacing and spacing tokens

Component spacing should generally not change with screen size: a button's padding is the same on a phone and a desktop. Layout spacing should: page margins, section gaps and grid gutters grow with available space. Encode that split in tokens:

/* Tier 1: primitive scale (never changes with breakpoint) */
--space-2: 8px;  --space-4: 16px;  --space-6: 24px;  --space-10: 40px;  --space-16: 64px;

/* Tier 2: semantic layout spacing (responsive) */
--space-page-margin:  var(--space-4);     /* 16px on compact screens   */
--space-section-gap:  var(--space-10);
@media (min-width: 840px) {
  --space-page-margin: var(--space-6);   /* 24px on medium and up      */
  --space-section-gap: var(--space-16);
}

/* Tier 2: semantic component spacing (density-aware, not responsive) */
--space-control-inset-x: var(--space-3);

Common spacing mistakes

Mistake

Off-scale "just this once" values

Each one is harmless; fifty are a second, invisible spacing system. Lint for raw pixel values in spacing properties.

Mistake

Equal spacing everywhere

Using 16px for everything removes the proximity signal. Groups disappear. Vary space deliberately by level.

Mistake

Margins on components

Components that carry their own outer margin collide unpredictably. Let parents own the space between children (CSS gap).

Mistake

Ignoring line-height in vertical spacing

A 16px gap between two text blocks with loose line-heights looks larger than 16px. Align text to the same 4px grid so measured and perceived space match.

Spacing checklist

  • Base unit chosen (4px with an 8px rhythm recommended)
  • Closed scale of ~12–14 values, dense small, sparse large
  • Token names guessable from values
  • Inset / stack / inline vocabulary in specs
  • Proximity rule: within-group < between-group, by 2+ steps
  • Density modes remap tokens; touch targets ≥ 24px (AA), 44–48 on touch
  • Component spacing fixed; layout spacing responsive
  • Lint against raw spacing values
